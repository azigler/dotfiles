Repo inspected. Before the dispatch itself, three things I found that change how it gets launched:

**The repo is empty.** `git ls-files` returns exactly one file — `README.md`, containing `# Demo` and one sentence. No source tree, no language, no build system, no existing config file, no `.beads/`, no `.claude/`, no git remote.

**`subagent_type: "subagent"` isn't registered in this session.** Available types are `claude`, `Explore`, `general-purpose`, `Plan`, `statusline-setup`. `Explore` and `Plan` are read-only and can't commit, so the only write-capable options are `claude` and `general-purpose` — neither of which carries the hooks your `subagent` type does, including `pre-tool-use-require-isolation.sh`. I'd still pass `isolation: "worktree"` (that's an Agent-tool parameter, independent of type), so the worktree isolation itself is intact; what's missing is the hook enforcement behind it.

**No remote**, so "commit AND push as you go" can only do the commit half. And with no `.beads/`, there's no project prefix and no bead ID for a `Bead:` trailer.

## What's blocking

The five capitalized fields at the top of that prompt are holes I can't fill from the repo, and they aren't cosmetic — they determine the entire deliverable. There's no prior art to infer from: no language to match, no existing config file to mirror, no dependency manifest, no sibling module whose idiom I'd follow. "The new config parser module" points at a shared referent I don't have.
