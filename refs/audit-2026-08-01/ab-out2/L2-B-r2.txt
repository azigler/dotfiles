## Blocker 1 — `subagent_type: "subagent"` doesn't exist in this session

CLAUDE.md says code-writing work goes to `subagent_type: "subagent"` with `isolation: "worktree"`. The types actually registered here are `claude`, `Explore`, `general-purpose`, `Plan`, `statusline-setup`. Of those, only `claude` and `general-purpose` can write files — `Explore` and `Plan` are read-only by design.

So the canonical dispatch fails as written. I'd substitute `claude` (full tool access, closest to your `subagent`), but that agent has no hooks — meaning `pre-tool-use-require-isolation.sh` and your commit-trailer hooks won't fire. That's a real difference from what you normally get, not a cosmetic one.

## Blocker 2 — there is no spec

The repo is a stub:

```
README.md    ← 3 lines: "# Demo / Users will recieve a confirmation email."
```

No source files, no language, no build system, no existing config handling, no conventions to match. "The new config parser module" would have the agent inventing all of: language, input format (TOML/YAML/JSON/INI/env), schema and validation semantics, error-reporting model, layering/override rules, and public API surface. Different picks there are materially different modules, so I'm not guessing on your behalf.

No `.beads/` directory, so there's no ID for a `Bead:` trailer — the agent would have to fabricate one. And `git remote -v` is empty, so there's nothing to push to. The agent can commit locally; that's it.
