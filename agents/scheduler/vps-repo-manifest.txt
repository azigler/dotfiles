# Directives (whitespace separated; ~ and $HOME expand; # starts a comment):
#
#   repo      <path> <remote> <branch>
#       A git checkout the VPS must keep at the branch tip. Fast-forward only.
#
#   submodule <repo> <subpath> <branch>
#       A submodule to init + track at ITS OWN branch tip.
#       NOT `submodule update` to the umbrella's pinned gitlink — measured
#       2026-07-26, the umbrella pin lags the submodule tip by days (pin
#       3ea2ce0 vs tip eb5d93e for dashboard-dev-interrupted), so pinning
#       would make the VPS run OLDER code than zig-computer, which is the
#       exact confidently-wrong failure this whole mechanism exists to stop.
#       Submodules NOT listed here stay deinitialized — agent-factory alone is
#       4.9 GB and this is a shared box.
#
#   readonly  <repo>
#       WATCH this checkout: report any dirty tracked file, and assert HEAD is at
#       the published tip. The directive name is historical twice over now.
#       It does NOT mean the VPS may not write — the box is a peer with a git
#       identity that commits and pushes (Zig, 2026-07-28) — and since
#       2026-07-30 (dotfiles-f4ub) it does NOT mean the checkout must end clean
#       either. Dirty is normal, dirty is somebody's WIP, and dirty never blocks:
#       the paths are recorded in the receipt's `dirty` array, carried into the
#       tick's DISPATCH.md and into the ledger row, and NOTHING resets them. A
#       single uncommitted edit used to fail the refresh for EVERY dispatched row
#       on the box, and on 2026-07-30 it did exactly that.
#       What still blocks is DIVERGENCE, judged by vps-preflight on the machine
#       Zig watches — and since 2026-07-31 (dotfiles-w16i) that means a HEAD the
#       published tip cannot reach by a fast-forward. A checkout merely BEHIND the
#       tip is the routine state of a peer fleet: the preflight fast-forwards it
#       (which cannot lose work), records the from/to shas in the ledger row, and
#       proceeds. AHEAD (push it) and genuinely diverged still stop for a human.
#
#   beadstore <repo> <path>
#       Fingerprint a bead store and record whether it changed since the previous
#       refresh. The VPS MAY write beads (Zig, 2026-07-28) provided it goes
#       through git; the `jsonl-union` merge driver is registered on BOTH machines
#       and resolves concurrent writes by id, superseding the duplicate-id hazard
#       explore-7iz9 §3 guarded against. This stays as the tripwire that a
#       divergence gets noticed rather than silently absorbed.
#
#   harvest   <repo> <path>
#       A TRACKED file the remote tick legitimately writes (the pulse ledger).
#       Before pulling, a COPY is preserved into the harvest dir so the row can
#       never be lost. The working copy is NOT reset — that reset was removed
#       2026-07-30 (dotfiles-f4ub): preserving a copy first does not make
#       destroying the working copy acceptable, and it is the same code path that
#       would have eaten verified benchmark-canon work. Listed in the receipt;
#       vps-preflight.sh copies the preserved version back to zig-computer.
#       Everything NOT listed here that is dirty is reported under `dirty` —
#       a warning, no longer a failure.
#
#   require   <path>
#       Must exist and be non-empty after the refresh. Catches the empty-submodule
#       class: an uninitialized submodule is an empty DIRECTORY, and a tick finding
#       no refs/pulse.md there looks like an empty project, not an error.
#
#   require-oob <path>
#       Same, but git can NEVER deliver it — it is gitignored or otherwise
#       local-only, so a failure here means "copy it out of band", not "pull again".

# The IMC campaign folders are gitignored in the umbrella (.gitignore:21-22), so
# NO amount of pulling will ever put them on the VPS. refs/beats.md points every
# beat at `~/linearb/imc-<month>` and guest-promo's /di-marketing-post frames its
# blurb from that corpus — a tick without it drafts confidently without campaign
# context. GLOB: every campaign folder, present and future. imc-* is gitignored in
# the umbrella and is NOT a submodule, so the UMBRELLA's git can never deliver it,
# and adding one would only create a gitlink the box cannot resolve.
# ⚠️ This asserts PRESENCE only — it no longer implies an rsync. Each campaign has
# its own remote and the box pulls it itself; see the `oob-exclude imc-*` block at
# the bottom, which exists because the rsync path deleted committed work.
require-oob-untracked $HOME/linearb

# lb-granola reaches the box by its OWN transport and must NOT also be rsync'd
# (bead dotfiles-f5tg (VPS side: lbg-y1y), 2026-07-28). It is a nested independent repo — its own remote is
# azigler/lb-granola, which this box's PAT CAN reach — so marketing-vps pulls it
# directly on a 2-minute timer (~/bin/lb-granola-pull.sh). Two reasons it is
# declared out of the complement tier rather than left to ride along:
#
#   1. FRESHNESS. As out-of-band cargo the corpus only moved when an unrelated
#      pulse tick was dispatched. Measured 2026-07-28: a meeting delivered
#      17:08:48Z arrived 18:44:39Z — 1h36m — and would have waited days over a
#      quiet weekend. Git polling makes it minutes, on any machine, and needs no
#      tailnet (this box is not on the tailnet).
#   2. TWO WRITERS. `rsync -az --delete` over a git working tree dirties it
#      relative to HEAD, which is the same "git and rsync would fight over the
#      same files" argument the complement rule itself makes above.
#
# Confidentiality note, since this is the line that decides it: the corpus is
# LinearB-confidential (client meetings, 1:1s) and this box is a SHARED team disk
# with login accounts for ben, kevin, mike and ubuntu. It was never a DECISION to
# push it here — it happened because the corpus is untracked by the umbrella.
oob-exclude $HOME/linearb/lb-granola

# The imc-<month> campaign folders reach the box by their OWN remotes and must NOT
# also be rsync'd (2026-07-30). Same root cause lb-granola hit, and that script's
# own header already names it: "the complement rule could not tell 'git does not
# own this' from 'a different git owns this'". Every /bootstrap-imc run creates
# `~/linearb/imc-<month>` as its own repo with its own remote
# (lb-marketing/imc-<month>), which this box's PAT can reach.
#
# For granola the symptom was staleness. Here it was DESTRUCTIVE, which is why this
# is a glob rather than one line per campaign:
#   `rsync -az --delete --exclude='.git/'` from zig-computer deletes any file the
#   VPS has that zig does not, while leaving .git intact. Git then reports those as
#   deletions, and a subsequent `git add <dir>` stages them. On 2026-07-30, with
#   zig's imc-aug26 checkout 11 commits behind, this removed 12 committed script
#   files from the VPS working tree twice, and two commits captured the deletions
#   as though they were intentional.
#
# marketing-vps instead polls each campaign repo directly: imc-pull.sh, every 10
# minutes, ff-only so it can never discard a commit made on the box.
oob-exclude $HOME/linearb/imc-*
